# ヴァイスシュバルツ 大会結果 集計・可視化サイト

ヴァイスシュバルツ(TCG)の大会結果を蓄積し、デッキの使用率・優勝率・カード採用率を可視化するサイトです。デッキタイトルごとのタイル一覧(メタゲーム、`index.html`)、タイルクリックで新しいタブで開くデッキ詳細ページ(`deck.html`、カード採用率など)、右サイドバーの直近の大会結果一覧を表示します(MTGGoldfishのメタゲームページを参考にしたレイアウトです)。大会名をクリックすると、その大会1件分の結果一覧ページ(`tournament.html`)が新しいタブで開きます。

## 構成

```
/docs/    公開用サイト(閲覧専用の静的サイト)
/admin/   非公開のローカル専用ツール(大会結果の入力用)
```

- `docs/` はデータの追加・変更ができる仕組みを一切持たない、閲覧専用のページです。安全に公開できます。
- `admin/` は大会結果を入力し `docs/data/tournaments.json` の元になるJSONファイルを作るためのツールです。**公開してはいけません。**
  - 実際のセキュリティは「`admin/`を見せない」ことではなく、「公開サイト(`docs/`)側にデータを書き込むAPI・仕組みが存在しないこと」そのものです。`admin/`はあくまでフォルダを分けて公開対象から外しているだけなので、リポジトリを公開設定にする場合は`admin/`が公開されないよう、必ずデプロイ元フォルダを`docs/`に限定してください。

## データスキーマ

### `docs/data/tournaments.json`(大会結果)

```json
[
  {
    "id": "2026-08-20-001",
    "eventName": "○○杯",
    "date": "2026-08-20",
    "organizerType": "official",
    "tournamentFormat": "single",
    "sourceUrl": "https://x.com/...",
    "results": [
      {
        "rank": 1,
        "team": 1,
        "deckTitle": "作品タイトル",
        "climax": ["扉", "宝"],
        "cards": [ { "name": "カード名", "count": 4 } ],
        "photoUrl": "https://..."
      }
    ]
  }
]
```

- 必須: `id`, `eventName`, `date`, `organizerType`(`official` | `individual`), `tournamentFormat`(`single` | `trio`), `results[].rank`, `results[].deckTitle`
- 任意: `sourceUrl`, `results[].team`, `results[].climax`(空配列可), `results[].cards`(未記録なら空配列), `results[].photoUrl`
- プレイヤー名は扱いません(友人など身近な範囲で公開する運用のため、個人が特定される情報は載せない方針です)。
- `results[].photoUrl`: X(旧Twitter)の画像などから、カードを1枚ずつ手入力できない場合の代替。デッキ詳細ページでは`cards`が空でも`photoUrl`があればカード一覧の代わりにこの画像を表示します。あくまで見た目の代替なので、カード採用率・平均枚数の集計には含まれません(集計は`cards`が入っている記録のみが対象)。
- `tournamentFormat`: `single`=シングル(個人戦)、`trio`=トリオ(3on3チーム戦)。トリオは各順位が3人1組のチーム単位で結果が並びます。
- `results[].rank` の意味は固定です: `1`=優勝, `2`=準優勝, `3`=TOP4(TOP4は複数人が同じ`rank=3`を共有します)。
- `results[].team`: トリオのときだけ意味を持つ整数。優勝チーム=`1`、準優勝チーム=`2`、TOP4の1チーム目=`3`、2チーム目=`4`…。シングルのときは省略します。
- `results[].climax`: 採用しているクライマックスカードの構成(複数選択可、未記録なら空配列)。選択肢と並び順は次項参照。

### クライマックス構成とデッキ表示ラベル

クライマックスの選択肢は次の13種類固定です(この並び順がキャノニカル順=表示順=保存順です)。

```
袋 / 扉 / 風 / 本 / ショット / 宝 / 門 / 電源 / 枝 / 筒 / チャンス / フォーカス / +2
```

`results[].climax` とデッキタイトルから、タイル表示・集計・画像マスタ照合に使う「デッキ表示ラベル」を次の規則で生成します:

- クライマックス未選択 → タイトルのみ(例: `あおぎり高校`)
- 1種類のみ選択 → `{タイトル} 8{クライマックス名}`(例: `あおぎり高校 8門`)
- 2種類以上選択 → `{タイトル} {クライマックスをキャノニカル順で連結}`(例: 扉・宝を選択 → `あおぎり高校 扉宝`)

**この「タイトル+クライマックス」の組み合わせを1つのデッキ(アーキタイプ)として扱い、使用率・優勝率・カード採用率もこの単位で集計します。** 同じタイトルでもクライマックス構成が違えば別のタイルとして表示されます。

このロジック(`CLIMAX_OPTIONS`定数と`buildDeckLabel`相当の関数)は `docs/js/common.js`・`admin/js/admin.js`・`admin/js/deck-images.js`・`admin/js/card-master.js` の4ファイルにそれぞれ実装されています。ビルド工程を持たない都合で共有モジュール化していないため、**クライマックスの選択肢を追加・変更する場合はこの4ファイルを同時に修正してください**。

### `docs/data/deckImages.json`(代表画像マスタ)

```json
[
  { "title": "あおぎり高校", "climax": ["扉", "宝"], "imageUrl": "https://..." }
]
```

「タイトル+クライマックス構成」ごとに代表カード画像のURLを1件だけ登録しておくマスタです。大会結果側(`tournaments.json`)には画像URLを持たせず、公開サイト側でタイトル+クライマックスが一致するマスタエントリを検索して画像を決定します。一致するエントリがない、またはURLの読み込みに失敗した場合はプレースホルダー表示にフォールバックします。

### `docs/data/cards.json`(カードマスタ)

```json
[
  { "name": "カード名", "type": "character", "level": 1, "climaxType": null, "imageUrl": "https://..." },
  { "name": "クライマックスカード名", "type": "climax", "level": null, "climaxType": "扉", "imageUrl": "https://..." }
]
```

カード1枚ごとに種別・レベル・(クライマックスの場合のみ)クライマックス種別・代表画像URLを登録しておくマスタです。用途は3つあります:

- **デッキ詳細ページのカードリスト並び替え**: 「種別(キャラ→イベント→クライマックス→未登録)→レベル昇順」でグループ化して表示します。未登録のカードは「その他(未登録)」として末尾に表示されます。
- **カード名のマウスオーバー画像プレビュー**: `imageUrl`が登録されているカードは、デッキ詳細ページでカード名にマウスを乗せると画像がポップアップ表示されます。
- **クライマックス構成の自動検出**: `type`が`climax`のカードは、管理ツールの大会結果入力タブで一括貼り付けを解析した際のクライマックス自動検出にも使われます(旧・クライマックスカード管理タブの機能を統合したものです)。

`level`はクライマックス以外のカードで使う整数(通常0〜3)、`climaxType`はクライマックスカードのときだけ`CLIMAX_OPTIONS`の13種類のいずれかを設定します。

## 指標の定義

このサイトは手作業で見つけた大会結果を積み上げたものであり、**全対戦の統計的サンプルではありません**(上位のみが記録される傾向があります)。数値は参考値です。

- **デッキ使用率**(タイルの「使用率」): フィルタ後の全デッキ枠数を分母に、デッキ表示ラベルが一致する件数を分子とした割合。分母が0件のときは「対象データなし」と表示します。デッキタイトルが空欄の記録は「(タイトル未記入)」として独立表示します。
- **優勝率**(「勝率」の代替指標、タイルの「優勝率」): `そのデッキの優勝(rank=1)数 ÷ そのデッキの登場数`。必ずサンプル数(N)を併記し、N<5は薄い色で表示します。
- **カード採用率**(タイルクリックで新しいタブで開くデッキ詳細ページ`deck.html`に表示): 選んだデッキ(タイトル+クライマックス)の記録デッキのうち、**カードリストが記録されているデッキだけ**を母数にした`そのカードを含むデッキ数 ÷ 母数`。平均採用枚数も同じ母数で計算します(カードリストが空のデッキは分母・分子どちらにも含めません。使用率・優勝率はカード未記録のデッキも含めて計算するため、母数が異なる点に注意してください)。タイル上には採用率上位3枚のみ抜粋表示します。
- **急上昇バッジ**(タイル左上に「急上昇」表示): 現在選択中の期間(例: 直近30日)の登場件数と、その直前の同じ長さの期間(例: その前の30日)の登場件数を比べ、直近の件数が2件以上かつ直前より2件以上増えているデッキに付きます(`docs/js/main.js`の`TRENDING_MIN_COUNT`・`TRENDING_MIN_DELTA`で閾値を調整可能)。主催区分・大会形式の絞り込みは現在のフィルタに合わせて両期間に適用されます。期間フィルタが「全期間」のときは比較対象がないため表示されません。

いずれも表記ゆれ(カード名・タイトル名の揺れ)を吸収する機能はありません。入力時になるべく表記を統一してください。

## デッキ詳細ページ(`docs/deck.html`)

メタゲームページ(`index.html`)のタイル、または右サイドバーの大会結果一覧のデッキ名をクリックすると、そのデッキの詳細ページが新しいタブで開きます。URLはクエリパラメータでデッキを指定するだけの汎用ページです(デッキごとにファイルを事前生成する方式ではありません)。

```
deck.html?title=あおぎり高校&climax=扉,宝&organizerType=official&tournamentFormat=single&period=60
```

- `title`(必須)・`climax`(カンマ区切り、任意): 表示するデッキを特定するキー。メタゲームページと同じ「タイトル+クライマックス構成」の単位です。
- `organizerType`・`tournamentFormat`・`period`(任意): メタゲームページで選択していたフィルタをそのまま引き継ぎ、同じ条件で使用率・優勝率・カード採用率を計算します。省略時は絞り込みなし(全期間・すべての主催区分・すべての形式)になります。
- `entryEvent`・`entryIndex`(任意): 大会結果一覧内の特定の1件(その大会・その順位で入賞した時の記録)を指定します。「このデッキの記録」のリンクはこの形式で、その大会で実際に使われたデッキリストへ直接飛べるようになっています。省略時は「最新の入賞デッキリスト」(カードリストが記録されている中で一番新しい記録。無ければ単純に最新の記録)を自動表示します。

ページの構成:

- ヘッダー: デッキ名・使用率・優勝率・代表画像・絞り込み条件のキャプション
- **最新の入賞デッキリスト**(または`entryEvent`/`entryIndex`指定時はその大会での入賞デッキリスト): 大会名・順位・日付と、使用カードを「種別(キャラ→イベント→クライマックス→未登録)→レベル昇順」でグループ化して表示します。`docs/data/cards.json`に画像が登録されているカードは、カード名にマウスオーバーすると画像がポップアップ表示されます。
- **カード採用率**(全記録の集計、カードリストが記録されているデッキのみが対象)
- 右サイドバー: そのデッキが登場した大会の記録一覧(日付・大会名・順位、各行が入賞時デッキリストへのリンク。出典URLがある場合は別途「(出典)」リンクも表示)

このURL構造により、デッキ詳細ページはブックマークや共有が可能です(ただしデータは`docs/data/`のJSONを都度読み込んで計算するため、リンク先の内容はデータ更新に応じて変わります)。

## 大会結果一覧ページ(`docs/tournament.html`)

メタゲームページ右サイドバー「最近の大会結果」の大会名をクリックすると、その大会1件分の結果一覧が新しいタブで開きます。

```
tournament.html?event=2026-08-20-001
```

- `event`(必須): `docs/data/tournaments.json`内の大会`id`。
- ページの構成: 大会名・主催区分・大会形式・日付(・出典URLがあれば「出典」リンク)のヘッダーと、順位・デッキ(`deck.html`のその入賞デッキリストへのリンク)の結果一覧テーブル。トリオ形式の場合は順位欄に「チームN」を併記し、同じチームの3人をグルーピングして把握しやすくしています。
- `deck.html`側(大会名リンク・「このデッキの記録」の各行)は元々その記録・そのデッキへ直接リンクする作りのため、このページへのリンクには変更していません。

## 管理ツールの使い方(`admin/index.html`)

`admin/index.html` はタブで「大会結果入力」「代表画像マスタ管理」「カードマスタ管理」を切り替えます。

### 大会結果入力タブ

1. `admin/index.html` をブラウザでダブルクリックして開きます(サーバー不要)。
2. 「1. 既存データの読み込み」で現在の `docs/data/tournaments.json` を選択して読み込みます(初回は未読み込みのままでOK)。読み込んだ大会は「読み込み済みの大会一覧」に表示され、各行の「削除」ボタンで大会ごとその場で削除できます(削除後は「JSONをダウンロード」で反映してください)。
   - 登録済みの結果1件だけ(デッキタイトルの誤字、カード枚数の間違いなど)を直したい場合は、大会一覧の「結果を編集」ボタンから「結果の個別修正」パネルを開きます。修正したい行の「編集」を押すと、通常の入力フォームと同じ内容(順位・チーム番号・デッキタイトル・クライマックス構成・カード表・一括貼り付け・デッキ画像URL)が既存の値で埋まった状態で開くので、直して「保存」を押します。大会全体を削除して入力し直す必要はありません。この編集でも、新しく入力したタイトルやカードがあれば通常の追加時と同様に画像マスタ・カードマスタへの自動仮登録が行われます。
3. 「2. 大会情報」に大会名・日付・主催区分・大会形式(シングル/トリオ)などを入力します。IDは未入力なら「自動生成」ボタンで `日付-連番` の形式が提案されます。
4. 「3. 結果」は大会形式に応じて自動的に構成が変わります。
   - **シングル**: 優勝1枠・準優勝1枠(固定)、TOP4は初期2枠で「+」ボタンで1枠ずつ追加、各枠に「削除」ボタン。
   - **トリオ**: 優勝チーム(3人)・準優勝チーム(3人)が固定、TOP4は初期2チーム(6人)で「+」ボタンでチーム(3人)単位に追加、各チームに「このチームを削除」ボタン。
   - 大会形式を後から変更すると、入力済みの結果欄がリセットされます(確認ダイアログが出ます)。
5. 各枠にはデッキタイトル・クライマックス構成(複数選択可)・使用カードを入力します。デッキタイトル欄は、読み込み済みの大会結果と代表画像マスタに登場した過去のタイトルからオートコンプリート候補が出ます(表記ゆれ防止のため、既存のタイトルがあればなるべくそこから選んでください)。カードは1行ずつ入力するか、一括貼り付け欄に貼り付けて「解析してカード表に反映」を押すと自動でカード表に変換されます。
   - 対応書式: `4x カード名` / `カード名 x4` / `4枚 カード名` / `カード名 4枚` / `4 カード名` / `カード名\t4`(タブ区切り)
   - `#` で始まる行はコメントとして無視されます。
   - 解釈できなかった行はエラー欄にそのまま表示されます(自動では削除されません)。手動でカード表を修正してください。
   - 同名カードが複数行あった場合は自動で合算され、合算した旨が表示されます。
   - 解析した直後に、カードリストの中に「カードマスタ管理」タブに種別=クライマックスとして登録済みのカードがあれば、そのクライマックス種別のチェックボックスが自動でオンになります(検出した種別は青字で表示されます)。未登録のカードや誤検出はチェックボックスを手動で修正してください。
   - 公式主催大会でデッキログ(decklog.bushiroad.com)にデッキが登録されている場合は、`admin/bookmarklet/install.html` のブックマークレットを使うとデッキ名・カードリストをデッキログのページから直接コピーしてここに貼り付けられます(詳細は同ファイル内の使い方を参照)。
   - X(旧Twitter)の画像などからカードを1枚ずつ読み取れない場合は、カード表を空のままにして代わりに「デッキ画像URL」欄にその画像のURLを入力できます。公開サイトのデッキ詳細ページでは、カード一覧の代わりにこの画像が表示されます(カード採用率などの集計には含まれません)。
6. 「この大会を追加」で読み込み済みデータに追加されます(件数が増えます)。**このとき、結果内で使われたタイトル+クライマックスの組み合わせのうち「代表画像マスタ管理」タブにまだ無いものが画像URL空欄の状態で、使われたカード名のうち「カードマスタ管理」タブにまだ無いものが種別・レベル未設定の状態で、それぞれ自動的に仮登録されます**(既存のものは重複登録しません)。あとは該当タブで内容を埋めるだけで済みます。
7. 「JSONをダウンロード」で更新後の全データを `tournaments.json` としてダウンロードします(`docs/data/tournaments.json`と同じファイル名なので、そのままダウンロードフォルダから移動するだけで上書きできます。ブラウザの設定によっては`tournaments (1).json`のように連番が付く場合があるので、その場合はリネームしてください)。
8. ダウンロードしたファイルの中身を確認し、`docs/data/tournaments.json` に置き換えてコミット・公開してください。

### 代表画像マスタ管理タブ

1. 「1. 既存データの読み込み」で現在の `docs/data/deckImages.json` を読み込みます(初回は未読み込みのままでOK)。
2. 「2. 登録」でタイトル・クライマックス構成・画像URLを入力して「登録」します。同じ組み合わせが既にある場合は上書き確認が出ます。
3. 「3. 登録済み一覧」で内容を確認できます。各行の「編集」ボタンを押すと、そのエントリの内容が上の登録フォームに読み込まれるので、名前を打ち直さずに画像URLだけ追加・修正して「登録」できます。「削除」で一覧から取り除けます。
4. 「JSONをダウンロード」で `deckImages.json` としてダウンロードし、`docs/data/deckImages.json` に置き換えてコミット・公開してください。

### カードマスタ管理タブ

カード1枚ごとに「種別(キャラ/イベント/クライマックス)」「レベル(クライマックス以外)」「クライマックス種別(クライマックスのみ)」「画像URL」を登録するマスタです(`docs/data/cards.json`)。公開サイトのデッキ詳細ページでのカード並び替え・マウスオーバー画像表示と、大会結果入力タブでのクライマックス自動検出の両方に使われます(詳細はデータスキーマの節を参照)。

1. 「1. 既存データの読み込み」で現在の `docs/data/cards.json` を読み込みます(初回は未読み込みのままでOK)。
2. 「2. 登録」でカード名・種別を選び、種別に応じて表示される「レベル」(キャラ/イベント)または「クライマックス種別」(クライマックス、13種類から1つ選択)を入力します。画像URLは任意です。同じカード名が既にある場合は上書き確認が出ます。
   - 複数枚まとめて登録したい場合は、その下の「一括登録」欄に1行1件、タブまたはカンマ区切りで `カード名, 種別(キャラ/イベント/クライマックスまたはcharacter/event/climax), レベル(キャラ・イベント)またはクライマックス種別(クライマックス), 画像URL(任意)` の形式で貼り付け、「解析して登録」を押します。スプレッドシートの行をコピーしてそのまま貼り付けられます(タブ区切りが自動認識されます)。`#` で始まる行は無視されます。既存のカード名と重複する行がある場合はまとめて上書き確認が出ます(「いいえ」を選ぶと重複分はスキップし、新規分だけ登録されます)。解析できなかった行はエラー欄に理由付きで表示されます。
   - 公式カードリスト(ws-tcg.com/cardlist/)から一括登録用のテキストを作りたい場合は、`admin/bookmarklet/install.html` の「公式カードリスト貼り付けツール」ブックマークレットが使えます。カード詳細モーダルを開いたままカードを次々クリックしていくと、上記の一括登録フォーマットで1行ずつ自動的に集まっていきます(クライマックス種別だけは公式ページに情報が無いため貼り付け後に手動で追記してください)。
3. 「3. 登録済み一覧」で内容(画像サムネイル含む)を確認できます。各行の「編集」ボタンを押すと、そのエントリの内容が上の登録フォームに読み込まれます(大会結果入力タブで自動的に仮登録されたカードは種別・レベルが空なので、まずこのボタンでカード名を呼び出してから埋めるのが楽です)。「削除」で一覧から取り除けます。
4. 「JSONをダウンロード」で `cards.json` としてダウンロードし、`docs/data/cards.json` に置き換えてコミット・公開してください。

種別を「クライマックス」で登録しておくと、大会結果入力タブで一括貼り付けを解析した際に、カードリストの中の登録済みクライマックスカードから自動でクライマックス構成を検出します。未登録のカードは検出されず、並び替えでは「その他(未登録)」扱いになりますが、大会結果を追加すると使われたカードが自動的に仮登録される(種別・レベル未設定)ので、「3. 登録済み一覧」で仮登録分の「編集」ボタンから内容を埋めていくのが基本の運用です。

(旧・クライマックスカード管理タブと`admin/data/climaxCards.json`はこのタブに統合されました。既存データは`docs/data/cards.json`に移行済みで、古いファイルは`_to_delete/`に退避してあります。)

## 公開サイトのローカルプレビュー

`docs/index.html` は `fetch()` で `data/tournaments.json` を読み込むため、`file://` で直接開くとブラウザのCORS制限で失敗します(「データの読み込みに失敗しました: Failed to fetch」と表示されます)。ローカルで確認する場合は簡易サーバーを立ててください。

プロジェクト直下の **`start-server.bat`をダブルクリック**すると、`docs/`を8080番ポートで配信するサーバーが別ウィンドウ(「WS Server (docs)」)で起動し、自動的にブラウザで `http://localhost:8080/` が開きます。サーバーを止めたいときはその別ウィンドウを閉じてください(Python が必要です)。

手動でやる場合は次のいずれかでも同じです。

```
npx serve docs
# もしくは
python -m http.server --directory docs 8080
```

一方、`admin/index.html` は `fetch` を使わず `FileReader` / `Blob` ダウンロードのみで動作するため、サーバーなしでダブルクリックして開けます。

**注意**: `docs/`のHTML/JS/データを更新した後は、ブラウザの通常の再読み込みだと古いファイルがキャッシュから使われて表示が崩れたりエラーが出たりすることがあります(`start-server.bat`のPythonサーバーはキャッシュ制御ヘッダーを送らないため)。更新後は **強制リロード(Windows/LinuxはCtrl+Shift+R、MacはCmd+Shift+R)** で確認してください。

## GitHub Pagesでの公開手順(例)

1. このフォルダをGitHubリポジトリにpushします。
2. リポジトリの Settings → Pages で「Deploy from a branch」を選び、ブランチ `main` / フォルダ `/docs` を指定します。
3. 数分後に公開URLが発行されます。`admin/` はPagesの対象外なので公開されません。
4. リポジトリ自体を非公開にしたい場合、無料プランではPrivateリポジトリのPagesは使えません(GitHub Pro/Team/Enterprise、または `docs/` だけを別の公開リポジトリに配置する運用が必要です)。

## 既知の制限・今後の拡張余地

- タイトル名・カード名の表記ゆれを自動で吸収する機能はありません。将来的にエイリアス辞書(`aliases.json`)を用意する案があります。
- データは単一の `tournaments.json` にすべて格納しています。数百大会規模までは問題なく動作しますが、ファイルサイズがおおむね5MBを超えて読み込みが遅く感じる場合は、カード情報(`cards`)を別ファイル(`decks.json`)に分離し、集計に使う軽量な `tournaments.json`(順位・デッキタイトルのみ)と、カード採用率を見るときだけ遅延読み込みする `decks.json` に分割することを検討してください。
- 代表カード画像(`docs/data/deckImages.json`)はURLをそのまま参照する方式です。リンク切れ対策としてブラウザ側で読み込み失敗時にプレースホルダー表示へフォールバックしますが、画像ファイル自体はホスティングしていません。長期的に画像を残したい場合は、画像を`docs/`配下に同梱してその相対パスを`imageUrl`に指定することもできます。
- `CLIMAX_OPTIONS`(クライマックスの選択肢と並び順)は `docs/js/common.js`・`admin/js/admin.js`・`admin/js/deck-images.js`・`admin/js/card-master.js` の4ファイルに重複定義しています。選択肢を追加・変更する際は4ファイルを同時に更新してください。
- カードマスタ(`docs/data/cards.json`)への画像URLもURLをそのまま参照する方式で、代表画像マスタと同様にリンク切れの心配があります(マウスオーバー画像プレビューは画像読み込み失敗時に単に表示されないだけで、エラーにはなりません)。
